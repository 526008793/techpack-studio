# 制单助手

Windows 桌面工具：读取服装 PDF 技术资料，经人工核对后，使用内置模板或自己的服装制单模板生成可编辑 Excel。CAD 相关页和尺寸页中英对照，其他填写区域使用中文。支持裤装、夹克等款式，内容来自新 PDF。

[下载 Windows x64 安装包](https://github.com/526008793/techpack-studio/releases/latest)

## 使用

1. 运行 `TechPack-Studio-Setup-1.0.6-x64.exe` 安装，桌面快捷方式为“制单助手”，使用 ZHH 字母图标。新版覆盖安装会重建快捷方式并刷新图标。
2. 第一次可点击“查看 P4541 示例”，直接体验核对和导出，不需要 API Key。
3. 处理新资料时，在“模型与 API 设置”填写支持图片输入的模型服务地址、模型名称和 API Key。推理强度默认使用 `xhigh`，也可选择其他强度或“跟随服务默认”；所选模型需要支持该强度。
4. 选择 PDF，直接使用内置模板，或点击“选择其他模板”选择自己的 `.xlsx` / `.xls`。自定义模板可增减、改名和移动栏目，不强制包含 11 个工作表。然后点击“识别并整理资料”。
5. 核对款式、面辅料、尺寸、工艺和图片裁剪范围。缺失数据保持空白，导出时显示为待确认。
6. 点击“生成 Excel 制单”并选择保存位置。用 Excel 或 WPS 打开并查看打印预览。

识别结果可通过“保存资料”存为 JSON，下次导入继续修改。相同 PDF、模型、接口和推理强度的识别结果会在本机缓存。手动填写、导入已有资料和本地导出不需要调用模型。

左侧“已保存的模板规则”支持点击 `＋` 新增一行、双击修改文字、选中后右键删除。按 Enter 或点击其他位置保存编辑，按 Esc 取消。清单自动保存在当前电脑，重启后保留；当前编辑的是核对清单，文字改动不会自动改变下方的内置模板生成逻辑。

## 固定模板规则

- 面料分别列出，即使成分相同也不合并。
- 自动增加独立的“衬 / INTERLINING”，不编造规格和使用部位；在模板实际包含的面辅料、风险评估、耗料及留卡表中同步填写。
- 绣章行不标黄。
- “客人意见或邮件”保留所选模板的内容。
- “数量搭配及打样要求”页总计下方的说明保留模板全文、格式和合并区域；配色增加时整段下移，包括其中的原始英文，不重新生成条款。
- CAD 相关页、尺寸页保留中英对照；其他已识别的表使用中文名称、规格、部位、单位、备注和栏目。款号、品牌、人名、尺码和色号等原始标识保留。旧资料缺少中文的内容提示补充，不回填整段英文；常用英文色名可本地翻译，未知色名保留真实色号并提示确认。
- 风险评估会保留原文：`风险评估会意见：【版师在制版前找业务要客户原始资料或样衣照片，参考清晰图片做样】`。其他会议意见区域留给实际填写，不生成虚构会议记录。
- 尺寸与公差是数值，英寸支持分数显示；不推算缺少的尺码。
- 已匹配的工作表设置打印区域，A4 一页宽、一页高，按内容选择横向或纵向。

自定义模板根据常见服装制单标题、字段标签和表头识别用途与位置，不按固定表名、固定单元格写入。只处理原模板存在的工作表，保留名称与顺序，不补成 11 页。材料数量增加时自动扩行；已有字体、边框、栏目与公司标识尽量保留，按实际字体调整换行和行高；有新配色内容的隐藏列会显示出来。实测覆盖 12 表夹克模板，以及减少工作表、工作表改名、栏目移动和列顺序变化。

款式图、CAD 工艺图、辅料及唛头参考图从新 PDF 提取，尺寸按新 PDF 的项目填写，不沿用模板内的旧款图片或裤装尺寸。PDF 没有提供对应图片时显示待确认，不生成虚构的 CAD 图。

CAD 页的中文译文按新 PDF 中的英文标注位置，放在附近的空白处，使用蓝色、可编辑的 Excel 文本框。程序检查英文、轮廓、引线和其他中文的占位；分数与单位保持完整。图片参考页可预览蓝色标注、展开修改译文，导出后可在 Excel/WPS 中编辑和拖动文本框。已完整标注的工艺说明不再重复堆到图下；附近留白不足或裁剪遗漏时，在导出页列出具体提示，并在图下保留文字供人工调整。材料表仍按原有栏目填写。旧版保存的资料可继续导入，但没有位置数据时需要重新识别 PDF 才能自动标注。

无法明确识别的工作表保留原内容和打印设置，并在导出页提示“未自动填写”；无标签的旧值、无法读取的图片或公式会提示核对。模板仍需保留有意义的标题/栏目标签，不保证任意无标题的自由排版都能自动识别。使用内置模板和 `.xlsx` 不需要安装 Excel；打开导出文件需要 Excel 或 WPS。旧 `.xls` 自动转换需要 Microsoft Excel 或 LibreOffice，也可先用 WPS 另存为 `.xlsx`。WPS 的内嵌图片公式在其他转换器中可能失效，需核对提示位置。

## 模型与本地文件

PDF 在本机读取并渲染。点击识别后，PDF 页面图片及提取文字会发送到设置的模型服务。文件原件不覆盖，Excel 在本机生成。API Key 仅在主进程使用，选择记住时用系统加密保存，不写入 Excel、JSON 或应用日志。本地模型可通过兼容 Chat Completions 的服务地址连接。

实际识别准确性取决于模型和源文件，尤其需要核对尺寸、数量、颜色及唛头中的占位内容。

每台电脑需自行配置可访问的模型服务与该服务需要的 API Key，安装包不包含密钥。模型请求使用 Electron 的 Chromium 网络栈，跟随系统代理设置。连接失败时会显示服务域名及 DNS、代理、连接拒绝、超时或证书错误，便于定位；这不代表能自动连通被网络限制的服务。HTTP 401/403 等服务响应则需检查密钥、权限或服务商限制。

## 开发与打包

独立工程，Electron + Vue + TypeScript。PDF.js 读取和裁图；OOXML 局部编辑保留原模板的图片、样式及分页能力。模型支持 OpenAI Responses 的严格 JSON Schema，以及兼容 Chat Completions 的 JSON 返回。

```bash
npm ci
node node_modules/electron/install.js
node scripts/copy-pdf-assets.mjs
npm run dev
npm run check
npm run test:desktop
npm run package:win
```

需要 Node.js 22.16+。构建 Windows x64 NSIS 安装包使用 electron-builder 的原生 NSIS 工具集，不需要 Rosetta 或 Wine。使用 `signExecutable: false` 保留图标和版本信息编辑，当前交付包未配置商业代码签名证书。

测试覆盖：分数与数值尺寸、模板规则、不同款号和材料数量、缓存、密钥加密、API 结构及错误处理；桌面回归通过本机模拟 API 完整走通真实 7 页 PDF、核对、图片裁剪及 Excel 导出，不向云端发送测试资料。Windows 安装包静态检查与原生 Windows 安装运行是不同的验证步骤。
